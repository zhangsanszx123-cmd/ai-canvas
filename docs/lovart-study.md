日期：2026-11-25。用户要求登录 Lovart 学习产品交互，已由用户完成登录。本记录来自浏览器实际页面及已有项目浏览，属于竞品观察和建议，不代表已经确认要在 AI Canvas 实现。

参考页面：[首页](https://www.lovart.ai/)、[项目](https://www.lovart.ai/zh/projects)、[技能](https://www.lovart.ai/zh/skills)。已有画布仅用于观察，未发起生成、上传、收藏、重命名、删除或分享操作；临时输入的 `/`、`@` 已清空。

## 给 AI Canvas 的建议，尚未确认为开发需求

后续状态：用户已要求根据学习完善产品，本轮落实账号技能库、项目技能加入账号库、输入快捷引用及项目管理菜单；具体范围见 [PRD](prd.md) 的“根据 Lovart 学习完善创作流程”。下方仍是原始建议，未落实部分不自动视为后续必做范围。

1. 优先补足画布与 Agent 的联动：选中图片后，在输入区明确显示本次参考图；支持移除引用，发送后清空本次选择。让“选图—描述修改—查看结果”流程连续。
2. 在已有项目 Skill 上传能力基础上，增加账号级技能库及独立管理入口，再支持 `/` 搜索选择。账号级技能可以避免每次换项目都重复上传；需先确定项目技能与账号技能的继承和删除规则。
3. 为输入区补上 `/` 选技能、`@` 引用素材的提示；引用显示可识别的缩略图和名称，不要求用户记资源 ID。
4. 项目卡片可采用更多菜单集中放置重命名、删除；保留明确的确认反馈和移动端可达性。现有空草稿过滤逻辑继续沿用。
5. 结果卡片首先展示图片、配置摘要与可理解的执行状态，技术参数收进可展开详情；区分调用提交成功与图片任务完成，重试成功后保留清晰的历史说明。
6. 首页可先增加少量真实可用的 Skill 案例和业务分类，再评估是否需要素材库、多画布页面等扩展。案例必须对应实际能力，避免只有展示入口。

## 观察范围

- 这是对当前账号、当前版本和浏览器页面的观察，未逆向内部接口或推断模型实现。
- 未测试付费生成、失败重试、导入文件格式、空项目何时持久化、删除恢复、协作分享及大屏布局，不能据此认定其具体规则。
- Lovart 项目入口在未登录时提示登录；AI Canvas 已确认游客可以只读浏览全部现有项目，应继续遵循自己的产品决策。
- AI Canvas 已确认的默认 1K、空项目不进入列表、权限与私密内容保护继续有效；本记录不自动改变这些规则。
