# S3 兼容存储约定

## 已确认与待提供信息

用户已确认使用现有 S3 兼容存储，不使用 Supabase Storage。已接入 `.env` 中的 `S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET`、`S3_ENDPOINT` 和 `S3_REGION`，真实上传、签名读取、浏览器图片显示及结果转存均已通过测试，测试对象已清理。密钥不写入文档。

配置名称见 [环境变量说明](../environment.md)。`S3_FORCE_PATH_STYLE` 仅在服务商要求时启用，临时凭据才需要 `S3_SESSION_TOKEN`。实现使用 AWS SDK v3 的 S3 客户端和预签名工具，不假定兼容服务完全等同于 AWS。

## 上传与访问

- 默认私有 bucket。后端验证用户身份、文件内容和 10MB（10,000,000 字节）上限后上传，返回内部资源 ID 与临时预览地址。首版由服务端接收上传，不先引入浏览器直传和 multipart 分片。
- 输入只接收 PNG、JPEG、WebP。图片资源持久化对象 key、所有者、项目和尺寸，预览地址过期后重新签名。
- 对象 key 采用所有者、项目和资源 ID 构建，不能使用客户端提供的任意路径覆盖文件。项目创建前上传的资源先归属用户，创建项目时绑定。
- 本次提交给生图服务的参考地址由后端生成；画布选图复用原资源对象，无需再次上传，允许重新签名，不能固定复用已过期的签名链接。
- 提交模型用的签名读取地址初始有效期为 24 小时，但受凭据和服务商策略有效期限制；使用供应商无法读取的内网 endpoint 时，需配置公网读取方案后再接入。
- 普通页面预览使用短时地址，不保存完整签名 URL 到日志。生成结果异步转存同一 bucket，转存失败可单独重试。
- 未绑定项目且超过 24 小时的临时上传可由后台清理；不得清理仍被消息、节点或任务引用的资源。

预签名 URL 是临时授权，其权限和有效期受签名凭据约束，不能当成永久资源 ID。依据：[AWS 预签名 URL 文档](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。S3 兼容服务需另行联调。

## 服务配置与联调

- 应用凭据仅授予目标 bucket/前缀所需读写权限，临时文件清理所需删除权限单独明确。
- 验证上传、读取签名 URL、图片尺寸、Content-Type 及供应商能否读取该 URL。
- 首版上传经过服务端，无需为此启用浏览器跨域 PUT；后续如改为直传，应补充 CORS、上传前签名授权、上传后校验和回调接口。
- 转存只读取已知供应商响应中的 HTTPS 地址，限制跳转、超时、下载大小和目标主机，防止任意地址抓取。下载失败不覆盖已有的有效资源。
