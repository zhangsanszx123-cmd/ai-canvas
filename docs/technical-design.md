# 画布生图产品技术设计

## 状态与范围

本文件记录已实施的首版技术方案，数据库迁移已执行，产品交互以 [PRD](prd.md) 为准。已确认多用户自主注册、PostgreSQL 存账号和业务数据、独立认证库、现有 S3 兼容存储及 ToAPIs Nano Banana 2.1。SMTP 和真实付费生图验证范围见运行维护文档。

## 技术栈与边界

- 沿用 Next.js App Router、TypeScript、Tailwind CSS 和 `pg`，SQL 连接复用 `lib/db.ts`。认证选用 Better Auth，替换现有 Supabase Auth；账号和业务数据使用同一 PostgreSQL 实例。
- Better Auth 可直接使用 `pg.Pool`，认证表通过库的迁移工具生成并审阅，纳入版本化迁移。用户 ID 类型与认证库配置保持一致，不强行假定为 UUID；项目和资源 ID 使用 UUID。依据：[PostgreSQL 适配文档](https://better-auth.com/docs/adapters/postgresql)。
- 画布已使用 `@xyflow/react`，模型图标使用 `@lobehub/icons`，依赖已安装。
- 浏览器只调用本项目服务端接口。数据库连接、ToAPIs 请求、存储管理权限不进入浏览器。
- 暂不引入 ORM、Redis 或独立前端框架。迁移使用版本化 SQL 文件，在实现时放到 `db/migrations/`；不得在页面请求中自动建表。

## 数据模型

下表是逻辑模型；实际业务表为 `ac_projects`、`ac_assets`、`ac_tasks` 和 `ac_nodes`，已通过 SQL 迁移创建。认证表由 Better Auth 生成，UUID 类型保持一致。

| 实体 | 主要字段与约束 |
| --- | --- |
| `projects` | UUID 主键、所有者 ID、名称、封面资源 ID、模型配置 JSON、画布视口 JSON、版本号、创建及更新时间。 |
| `assets` | UUID 主键、项目 ID、所有者 ID、来源、bucket 对象 key 或远程地址、MIME、宽高、大小、转存状态。来源区分本地上传与生成结果。 |
| `messages` | 首版由 `ac_tasks` 的提示词、参考图、配置快照和结果派生，提供消息查询接口，不重复建立消息表。历史记录不随后续输入修改。 |
| `generation_tasks` | UUID 主键、项目 ID、所有者 ID、供应商模型、供应商任务 ID、请求快照、状态、进度、结果数、错误摘要、幂等键、查询时间、工作租约与重试信息。 |
| `canvas_nodes` | UUID 主键、项目 ID、任务 ID、资源 ID、节点类型、位置、展示尺寸、排序与版本信息。节点支持生成占位、结果图片和错误状态。 |

- UUID 由服务端生成；供应商任务 ID 与项目 ID、内部任务 ID 分开保存。
- 一个项目拥有多条生成消息、任务、图片和画布节点；一次生成可产生多张图片，按任务和结果序号建立唯一约束，重复查询不会插入重复节点。
- 删除失败占位只删除 `ac_nodes` 中已明确失败且 `asset_id IS NULL` 的节点，保留 `ac_tasks` 历史记录；服务端核对项目、节点归属和任务状态。删除完成后更新项目排序时间，不改变几何版本号；几何保存只更新已有节点，旧页面不会重建已删除占位。
- 存储对象 key 建议为 `{ownerId}/{projectId}/{assetId}.{ext}`。签名 URL 不作为永久资源标识，持久化对象 key，读取或提交生成前重新签名。
- 统一使用带时区时间戳，API 返回 ISO 8601；客户端按用户本地时区展示。
- 画布保存位置、尺寸、资源关联和视口，避免将 React 组件、临时地址或 base64 存入数据库。
- 图片节点使用 React Flow 四角控制点等比例调整展示尺寸；结束拖动后复用画布防抖保存与版本冲突处理，写入 `ac_nodes.width/height/x/y`。正在缩放或尚未保存时，轮询合并保留本地图片几何信息；生成占位更新为图片时仍使用服务端返回的初始尺寸。

## 认证与权限

- 多用户模式使用 Better Auth：服务端验证数据库会话后取得用户 ID，不能相信请求体中的所有者字段。初始采用邮箱密码登录，由认证库管理密码哈希、会话与 Cookie，不手写密码加密逻辑。
- 已增加 `lib/auth.ts`、客户端认证入口及 `/api/auth/[...all]`，替换原页面认证及 proxy 逻辑。生产 Cookie 使用 HttpOnly、Secure 及合理的 SameSite，写接口校验请求来源。最新确认自主注册无需邮件验证，注册后自动登录；找回密码仍使用限时单次邮件令牌，邮件服务未配置时单独提示不可用。
- 注册、登录和密码重置实施速率限制，密码重置避免暴露账号是否存在。认证密钥本地安全生成，邮件凭据仅服务端使用。生成额度与收费在公开上线前由用户确定。
- 项目、资源、消息、任务和画布接口逐次校验所有权；查不到或不属于当前用户时统一返回 404。
- 未登录 API 返回 JSON 401，页面才跳转登录页。现有 proxy 需要在开发时区分 API 与页面，不能让 API 返回登录 HTML。
- 已移除旧 Supabase proxy 的环境变量跳过逻辑；页面 proxy 只检查会话 Cookie，页面内容与业务接口继续独立验证真实会话。
- 启用 Cache Components 时，每个读取会话或运行时查询参数的页面使用自己的 `Suspense` 边界，将异步读取放入其子组件；根布局边界不能代替共享布局下的客户端导航边界。会话保持实时验证，不通过共享缓存或关闭即时导航检查来规避。
- `pg` 直连不会自动携带应用用户上下文。所有查询显式限制所有者，SQL 使用参数绑定。数据库启用 RLS 时需一并设计数据库角色和事务内身份上下文，不依赖 Supabase 的 `auth.uid()`，不假定当前连接角色一定受 RLS 约束。

## 异步任务与恢复

1. 验证会话、项目所有权、提示词、参考图可用性及模型配置。
2. 以客户端幂等键创建内部任务，事务内写入消息与占位节点；同一键重试返回同一任务，参数不一致返回冲突。
3. 服务端工作进程从 PostgreSQL 领取带租约的任务，调用供应商创建接口，落库供应商任务 ID；不能依赖浏览器持续打开，也不能在 Route Handler 返回后启动无保障的后台 Promise。
4. 使用已有供应商任务 ID 查询结果并更新本地状态。查询间隔初始为 5–10 秒并加入抖动，限流遵循 `Retry-After`，瞬时错误退避；一次只允许一个工作进程持有同一任务租约。
5. 成功后保存资源和结果节点，并转存生成图片到所选 bucket，避免把供应商临时 URL 当作永久图片地址。转存失败保留已有供应商结果并标记“图片保存失败”，重试转存，不重新收费生成。
6. 客户端查询本项目任务接口，刷新、退出重进后从数据库恢复状态；暂时断网不会自动创建新任务。

### 状态与异常规则

- 内部状态区分 `submitting`、`queued`、`in_progress`、`saving`、`completed`、`failed`、`submission_unknown`，供应商原始状态独立保存。
- 创建请求发生超时且不确定供应商是否受理时，标记 `submission_unknown`，不得自动重新 POST；需要核对供应商幂等或任务查找能力后处理。
- 轮询超过 15 分钟时提示“耗时较长”，降低查询频率；本地等待超时不等于供应商失败，不直接重新提交。
- 已明确失败后可由用户点击重试，形成新任务并提示会重新生成。首版不实现供应商取消，除非后续确认可用接口。
- 同一项目同时最多一个进行中的生成任务，服务端原子检查，多个标签页也不能绕过。另加用户级并发限制；具体额度和公开运营策略待使用范围明确。
- 多结果按实际返回保存；数量少于请求时保留成功图片并明确提示数量差异，不自动补单。
- 原始供应商错误可能含内部信息，只向前端返回可读摘要和内部任务 ID。日志隐藏令牌、连接串和签名 URL 查询参数。

## 存储与部署

- 使用现有 S3 兼容存储，统一封装上传、签名读取、转存三个操作，使用 AWS SDK v3 S3 客户端及签名工具；具体服务商、endpoint 和 region 由用户提供，细节见 [存储约定](api/storage.md)。
- 默认私有 bucket，服务端校验所有权后提供临时读取地址；提交给模型的 URL 必须在任务处理期间有效。初始签名有效期设为 24 小时，并在重试提交前刷新，是否满足供应商抓取规则需联调验证。
- 上传及画布选图均校验实际类型与大小，仅允许 PNG、JPEG、WebP，最大 10MB（10,000,000 字节）；前后端同时校验。本地选择与画布选择共用一个参考图槽位。
- 画布选择只接受当前项目、当前用户可访问的图片资源；浏览器传资源 ID，服务端取对应地址，不允许任意 URL 触发服务端抓取。
- 首版选择本机或容器化 Node.js 服务，额外启动持久工作进程，任务队列复用 PostgreSQL。若后续部署到仅请求生命周期的托管环境，需补充持久任务调度服务，不能直接假定平台支持常驻进程。
- 环境变量说明见 [environment.md](environment.md)。数据库模块已读取 `DB_CA_CERT`，使用证书校验；不以关闭验证代替证书配置。

- 数据库和存储已真实联调，ToAPIs 密钥通过模型列表只读检查。创建、查询与图片结果在自动测试中模拟，未调用付费生图。
- 已验证项目、上传、任务状态、真实结果转存及浏览器链路；真实模型的生成质量、耗时和最终计费不冒充已经验证。

- 运行 TypeScript、ESLint、构建检查；按参考图验证空状态、上传后、生成中及生成完成四类页面。拖动面板宽度始终约束在 320–620px。
