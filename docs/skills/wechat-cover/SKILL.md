# 公众号封面

将用户提供的 Markdown 文章制作成一组四张公众号封面。只使用当前项目现有的图片生成工具，不调用外部生图服务、不执行脚本。

## 先读文章并询问风格

1. 阅读本次附件里服务端提供的 Markdown 全文，包括标题、正文与结尾；不能只看文件名或首段。若没有文章全文，先请用户附上 Markdown，不凭空编造主题。
2. 用一句话概括核心主题，给出一个 4–10 个汉字的封面短标题；保留文章事实立场，避免夸张或无依据的数据。
3. **首次必须停下来询问用户选风格，不能在询问的同一条回复中生成图片，即使用户笼统说“直接生成”。** 按以下顺序展示五个选项：
   - 1 极简大字报
   - 2 杂志封面
   - 3 插画
   - 4 科技
   - 5 孟菲斯
4. 用户下一条回复数字或风格名称时，结合上一轮文章、主题及短标题继续，不要求再次上传文章或重新选择 Skill。若风格回答有歧义，先澄清，不擅自选择。

## 五种风格的视觉规则

| 风格 | 配色 | 构图与主体 | 字体 |
| --- | --- | --- | --- |
| 极简大字报 | 米白底、近黑主字、朱红小面积强调；三色以内 | 大量留白，标题占画面主体；最多一个贴合主题的几何物件或符号，强调编辑节奏 | 特粗中文黑体，笔画清晰，无花字；关键词可用朱红 |
| 杂志封面 | 奶油白或深灰基底，搭配一款文章主题强调色 | 一个鲜明的摄影感主视觉与有层次的文字；视觉有明确焦点，不堆砌栏目；可使用细线、留白和小号英文装饰，但不虚构杂志品牌 | 中文现代宋体主标题，细黑体辅助；不使用难辨识的装饰字 |
| 插画 | 暖米白、低饱和蓝绿、陶土橙；色彩温暖统一 | 将文章核心概念画成易懂的场景或物件，手绘线条、平涂与轻微纸张质感；标题有干净独立的区域 | 圆润清晰的中文黑体，不将文字画成无法阅读的涂鸦 |
| 科技 | 深海军蓝、冷白、少量青色或电光蓝强调 | 主题相关的结构、数据空间或抽象科技物件，清晰层次和克制发光；避免无意义电路铺满背景，不虚构科学结论 | 现代中文无衬线黑体；数字可用等宽字体；文字与背景保持高对比 |
| 孟菲斯 | 奶油白底，珊瑚红、钴蓝、明黄与黑色；统一限色 | 活泼的几何形状、波点与线条围绕主题主体，保留标题净空区；节奏鲜明，不能遮挡文字 | 粗中文无衬线黑体，允许少量倾斜排版；不使用多种互相冲突的字体 |

## 用户选择后，一次提交四张

- 沿用用户确认的**同一种风格、同一套配色、同一个短标题、同一字体方向**；不混搭四种风格。
- 使用宽幅 `size: "21:9"`、`resolution: "1k"`，适合公众号封面；所有关键文字和主体置于中部安全区，与四边至少留出约 8% 的距离，兼顾裁切。
- 四种构图必须明显区分：① 左侧大标题、右侧主体；② 居中标题与居中主视觉；③ 上标题、下方横向场景；④ 右侧标题、左侧近景主体。按照所选风格调整空间，避免仅换色或镜像复制。
- 每张提示词写完整：文章主题、短标题的精确中文内容、已选风格、统一配色、该张构图、字体与安全区。只保留必要标题文字，不把整篇文章塞进封面，不出现乱码、伪水印或未授权标志。
- 用现有 `generate_image` 工具**调用一次**：`prompt` 概述本次创作，`prompts` 数组包含四条完整提示词，`size` 为 `21:9`，`resolution` 为 `1k`。不要连续调用四次单图工具，不新建接口。
- 若用户明确要求使用图片参考，先逐一调用 `view_image` 真正查看，再按顺序传入 `referenceAssetIds`；纯文章封面不强行使用与主题无关的图。
- 工具返回四个任务 ID 后，告知“四张封面已提交，结果将进入生成记录和画布”。异步任务尚未完成时不能声称图片已完成；不要因为等待或网络中断重复提交。明确失败后才由用户决定是否重试。
